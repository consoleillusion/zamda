# Decisions

Settled questions and why. Add an entry when you change one; do not reopen one
in code. Newest last.

| ID | Decision | Why |
| --- | --- | --- |
| D-001 | The product is the DSL, the IR and the contract. Engines are backends. | Useful from the first milestone; the project survives if the WASM spike fails. |
| D-002 | The JS backend ships first and is the reference for every other backend. | No WASM risk early; it doubles as the test oracle; it serves small data. |
| D-003 | Expressions are type-checked eagerly, when each DSL method is called, through the registry. `compile()` then assembles, optimizes and validates. | Errors point at the user's line; the validator still re-checks everything, so the IR is safe from any source. |
| D-004 | JS-side validity is one byte per row, not a bit-packed bitmap. | Simpler and faster in JS. Bit-packing is an internal detail of the WASM backend. |
| D-005 | The type-mismatch error is named `TypeCheckError`. | The spec called it `TypeError`, which would shadow the JS built-in. |
| D-006 | `count` returns `uint32`. Row count is the free function `count()`; non-null count is `c.x.count()`. | Counts come back as plain JS numbers. A method on the accessor (`c.count()`) would collide with a column named `count`. No in-memory table here can exceed 4.29 billion rows. On Substrait export it is cast to `i64`. |
| D-007 | `groupBy` takes an object of named keys, `groupBy(c => ({ country: c.country }))`, not an array. | Output column names and types are inferred exactly, and computed keys get names. |
| D-008 | Until task T-102, binary operations need operands of the same type. | Keeps the first slice small. Promotion rules are already in the contract. |
| D-009 | Apache Arrow is an internal detail of the WASM backend. Users pass rows or typed arrays. Type names follow Arrow. | It is what front-end developers have; Arrow is still the right layout inside the engine. |
| D-010 | Integer arithmetic is checked by default. This is final. | The owner's first priority is reliability. Wrapping forms exist as explicit methods. |
| D-011 | Execution is chunked and cooperative; cancelling leaves tables intact. | Dashboards cancel on every interaction; reloading data each time is unusable. |
| D-012 | Groups come out in first-occurrence order. Float sums use Neumaier summation in row order. | Both make results identical across backends without extra sorting. |
| D-013 | Sugar lowers in the DSL. `between` becomes `gte` and `lte`; `bin` becomes arithmetic. | Fewer functions for every backend to implement and for Substrait to map. |
| D-014 | The runtime and toolchain is Bun, with `tsc` for type checking. | Owner's choice. |
| D-015 | Name: zamda. Licence: MIT. | Owner's choice. |
| D-016 | Append-only live tables are in Milestone 2; keyed live tables come first after the MVP. | A dashboard that moves is a stronger first release; keyed updates are a much larger engine feature. |
| D-017 | Contract refinements made while building aggregates: a `sum` is overflow-checked on every partial sum; a non-finite float running sum is returned as is; `-0.0` keys are reported as `0.0`; `avg` sums as `float64`; NaN is greatest for `min` and `max`. | Each was a gap in the contract that two backends could have filled differently. |
| D-018 | Group-by on 32-bit integer keys and integer distinct counts use open-addressing hash tables over typed arrays, not `Map` and `Set`. | Measured: 2.4x faster than `Map` on 75k groups over a million rows. See `docs/BENCHMARKS.md`. |
| D-019 | The executor skips copying columns no later node reads. | Cheap, and it never changes results. |
| D-020 | Parameters are declared on `pipe(schema, { name: type })` and reach callbacks as a second argument, `(c, p) => ...`. There is no free `param()` function. | The declaration gives `execute()` an exact parameter type with no extra machinery in every expression type. |
| D-021 | `cast` and `in` are IR expression kinds, not registry functions. | Each needs information a function signature cannot carry (a target type, a list), and each maps to its own Substrait expression. |
| D-022 | `timestamp` is whole milliseconds since the Unix epoch in UTC, with no unit or time zone parameter. `date32` rejects a `Date` that has a time of day. | It is exactly what a JS `Date` holds, so nothing is lost or guessed on the way in or out. Finer units can be added as new types. |
| D-023 | `lower` and `upper` return `utf8` even for a dictionary input. | Case mapping can merge entries, which would break the rule that dictionary entries are unique. |
| D-024 | `round` rounds ties to even. | It is the IEEE 754 default and avoids the upward bias of JS's `Math.round`. |
| D-025 | A JS literal operand takes the type of the expression it meets; only two expressions are promoted. Comparisons promote like arithmetic. | `c.small.add(1)` staying `int8` is predictable; widening on every literal would make result types depend on literal size. |
| D-026 | `filter` and `sort` produce a selection (row indexes) over their input; rows are copied only when a later operator needs dense columns. | Removes the copy that made filter-then-group slower than a hand-written loop. |
| D-027 | Dictionary entries are unique within a column, so equal codes mean equal strings. | Lets group-by, distinct counts and equality run on integer codes. |
| D-028 | The executor is a generator. A plan is cut into phases at the blocking operators (aggregate, sort, result); each phase reads its source in chunks through the streaming nodes into a sink; the driver resumes the generator until a time slice is used, then returns to the event loop. | One mechanism gives cancellation, progress and a responsive page, with no threads and no change to results. |
| D-029 | Aggregation state lives across chunks: a persistent group table, growable accumulators, and key values captured when a group first appears. Dictionary columns are mapped onto one canonical dictionary per key. | Chunks computed separately can carry different dictionaries, so raw codes cannot be compared between chunks. |
| D-030 | Runtime errors report the operation, type and offending values, not a row number. | Execution is chunked and rows may have been filtered, so a row position would be wrong. Loading errors still name the row. |
| D-031 | `limit` stops the scan as soon as it is satisfied. | It is free with chunked execution and makes previews of large tables instant. |
| D-032 | A superseded or aborted run rejects with `AbortError`, like `fetch`. `latest(plan)` aborts the previous run when a new one starts. | The standard shape; callers already know how to ignore it. |
| D-033 | A JS table is a list of immutable segments, one per `append`. `append` and the retain window build a new list and swap it in; a run captures the list when it starts. | Gives snapshot semantics with no locking and no copying: a run in progress can never see a half-appended table. |
| D-034 | The retain window keeps exactly `N` rows, trimming inside the oldest segment if needed, rather than dropping whole segments. | An exact window is easier to reason about and to test. Trimming a typed-array column is a view, not a copy. |
| D-035 | There is no change notification on a table. After `append`, the caller re-runs its queries, normally through `latest()`. | Keeps the table a plain data structure; the dashboard decides how often to refresh. |
| D-036 | The reference dataset comes from RIPE RIS (collector rrc00 by default), not RouteViews. | RIS dumps are gzip, which Bun decompresses natively; RouteViews uses bzip2, which would need a dependency. Both are full public routing tables. |
| D-037 | One row per IPv4 prefix: the entry with the shortest AS path, ties broken by the lowest peer index. Path length follows BGP: a set counts once, confederation segments not at all, prepends count. Prefixes whose chosen path has no single origin (empty, or ending in an AS_SET) are skipped and counted. | Deterministic for a given dump, and every row has a real origin AS, so `origin_as` needs no nulls. |
| D-038 | Network names come from RIPE's `asn.txt`; regions from the NRO combined delegation statistics. A network missing from either gets null. | Both are published daily by RIPE NCC alongside the dump, so one source host serves everything. |
| D-039 | The dataset is written as a compact columnar file (`data/routes.bin`) whose number columns load into a zamda table without copying. Byte order is little-endian, which every current browser and server platform uses. | A million rows load in about 0.2 s, against several seconds and roughly 100 MB for JSON. |
| D-040 | The prep script lives under `scripts/`, outside the published package. | It is tooling for the demo, not part of the library. |
| D-041 | A RIB entry whose path attributes cannot be decoded is skipped, counted and reported with its raw bytes; the run continues. A record whose entries run past its own end is still fatal. | Each entry carries its own length, so skipping one cannot desynchronise the reader. The first real run stopped on one such entry about 930,000 prefixes in. |
| D-042 | A downloaded dump is saved next to the output file and reused on later runs. | A rrc00 dump is hundreds of megabytes; re-downloading it to retry a run is wasteful. |
| D-043 | Grouping on several columns that are all stored as integers of 32 bits or fewer (including dictionary codes and dates) uses an open-addressing table of key tuples in a flat `Uint32Array`, with a dedicated loop for two keys. Other key combinations still use the string-encoded path. | On real routing data, grouping by network number and name took 194 ms through string keys; it is the dashboard's main chart. |
| D-044 | `min` and `max` of a dictionary column compare precomputed code-point ranks of the dictionary's entries, cached per dictionary, and fall back to string comparison only across different dictionaries. | Comparing strings row by row made taking a network's name with `max()` six times slower than counting. |
| D-045 | The JS backend takes three shortcuts that never change an answer. (1) `and`/`or` with a literal or parameter on one side skip the other side when Kleene logic decides the result (`x or true`, `x and false`) and return the other side when the constant is neutral. (2) A number column compared with a literal or parameter reads the value once; when the value covers the column's whole integer type (`>= 0` on a uint8) the answer is a fill. (3) An expression that reads one dictionary column and uses only functions that cannot fail is evaluated once per dictionary entry plus one null entry, cached per dictionary and parameter values, then gathered by code. A filter that keeps every row passes the batch through with no selection vector. | The dashboard's controls are parameters whose "off" values let every row through. Without these, a switched-off filter cost as much as an active one, and the name search lowered a million strings per keystroke: 44 ms down to 10 ms here. Only functions that cannot fail are allowed in (3), because dictionary entries no row uses are evaluated too. |
| D-046 | Dashboard charts are linked the crossfilter way: each chart applies every selection except its own, so a brushed histogram still shows the bars outside the brush. Every control is a plan parameter with a neutral value (full range, `allRegions`, `noSearch`), so plans are compiled once at start-up. Each chart runs through its own `latest()`. | Standard behaviour for linked charts, and no recompiling on input. Touching a chart re-runs the others; its own redraw reuses the counts it already has. |
| D-047 | The demo draws its charts as plain SVG with no chart library, and imports the routes file loader from `scripts/bgp/file.ts`. | Keeps the demo dependency-free and small enough to read; the demo is not part of the package, so it may use script code. |
| D-048 | RIS Live updates become one row per IPv4 prefix: `second`, `kind` (announce or withdraw), `prefix_len`, `origin_as`, `peer_asn`. The origin is the path's last AS, null when the path ends in a set and for withdrawals, which carry no path. IPv6 and malformed messages are dropped. The live table keeps the latest 200,000 updates; rows are buffered and appended once a second. | Matches the reference routes' IPv4-only scope. Appending in batches keeps segments few, and once a second is as often as the panel redraws. |

## Departures from design spec v4

The scaffold differs from the spec's code examples in three places, each
recorded above: D-005 (error name), D-006 (`count()` instead of `c.count()`),
D-007 (`groupBy` takes an object), D-020 (declared parameters) and D-022
(timestamps have no unit or time zone parameter).
